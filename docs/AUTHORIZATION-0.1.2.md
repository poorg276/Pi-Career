# PiCareer 0.1.2 授权修复与验收

日期：2026-10-10。基于本地 Pi SDK，未修改 pi-main 上游源码；用户数据结构与存储目录保持不变。

## 修复内容

- 点击订阅供应商的连接按钮后，立即显示独立授权弹窗。OpenAI Codex 默认浏览器登录，收到 SDK 授权地址后通过 Electron 主进程自动打开系统默认浏览器，每次尝试仅自动打开一次。
- 提供重新打开、复制链接、取消，以及 OpenAI Codex 设备码备用登录。设备码显示有效时间；手动回调输入折叠显示，输入错误自动滚入可见区域。
- 取消不再提交空授权码。每次登录具有独立 attemptId，授权输入与操作必须匹配当前尝试；取消信号与 SDK 的单次输入信号合并。
- 取消、失败、超时和后台退出都会清除链接、输入与验证码；重试重新生成授权地址，旧链接操作在主进程被拒绝。关闭应用后需要重新发起未完成的授权。
- 检测本地 1455 端口不可用的情况，给出中文提示和备用入口，不操作其他程序。
- 凭据保存后显示“已保存授权”，刷新模型列表并引导选择模型。授权成功与模型调用测试成功是两个不同状态，不自动选择或切换已保存的模型配置。
- API Key、OAuth 凭据继续由原有 Vault / Windows safeStorage 保存。授权诊断只展示错误分类，不记录授权码、令牌和完整回调地址。
- 加密等待期间若授权被取消，落盘前再次检查取消信号，保留原有凭据，不写入本轮新令牌。

## 实现接口

`login` 输入包含 provider、method（browser / device_code）和 attemptId，返回最终授权状态；`authorization` 事件推送当前进度。`cancelLogin` 和 `authReply` 关联尝试，`authLink` 只允许打开或复制当前仍有效的授权地址。供应商模型列表包含非秘密的 credentialType 状态。

SDK 的 PKCE、state 校验、令牌交换和刷新流程保持原样；SDK 支持的其他供应商输入、选项和设备码流程继续复用。普通文本输入可留空采用供应商默认值（如 GitHub 域名），手动授权码和密钥输入不能空提交。

1. 类型检查与单元测试：真实 Pi SDK 配合内存模拟令牌服务，验证浏览器回调、错误 state / 缺少 code、令牌交换、模型状态、凭据保存和重新载入；验证取消后 1455 端口可复用、重复提交、迟到输入、手动回调、设备码、输入取消、超时、网络失败、过期及禁用设备码的错误。
2. Electron 授权回归：实际后台进程和窗口，使用隔离数据目录；仅替换测试进程的浏览器打开和剪贴板函数，避免打开外部授权页面或覆盖用户剪贴板。验证滚动后立即弹窗、自动打开一次、复制、重新打开、空输入禁用、无效输入就地显示、取消、旧链接拒绝、端口占用、浏览器失败后重试、后台退出。
3. 原有集成流程：真实 Pi SDK 配合本地模型模拟服务，验证自定义 API、Windows 加密凭据、重启后的上下文、工具允许/拒绝、取消、8 题面试、113 条背诵计划及测验。桌面冒烟检查 Python 本地判题、学习推进和模型目录，无页面运行错误。
4. `npm run check` 通过；`npm test` 共 27 项通过，其中授权相关 11 项。最终打包版在 125% 与 150% 下通过授权桌面回归，无页面运行错误。见 [125% 结果](evidence/authorization-0.1.2-125.json)、[150% 结果](evidence/authorization-0.1.2-150.json)、[集成结果](evidence/integration-0.1.2.json)、[桌面冒烟结果](evidence/desktop-0.1.2.json)。

## 真实账号验证

**真实 OpenAI 账号登录与订阅模型调用：未验证。** 自动化没有访问真实账户或使用真实令牌，模拟令牌成功不能代替真实账号验收。

更新后打开“模型与设置”，在 OpenAI Codex 行点击“连接”，保持 PiCareer 开启，在系统浏览器完成账号选择和授权。弹窗显示已授权后，点击“选择模型”，选择模型、保存并测试连接。若浏览器回调无法打开，可在当前弹窗的备用区域粘贴完整回调地址；若本次授权已结束，需要重新连接，不使用上一轮的浏览器地址。

设备码登录是否可用取决于账户或工作区设置。参见 [OpenAI 官方授权说明](https://learn.chatgpt.com/docs/auth)。

已有 API 设置、凭据、聊天、代码草稿和学习进度均保留；本次不改动 YxAgent 或 pi-main。
