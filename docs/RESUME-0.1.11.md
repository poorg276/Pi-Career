# PiCareer 0.1.11 简历优化与完整简历制作

## 使用方法

侧栏删除原英文标语、中文说明及装饰线，新增「简历优化」；工作台保留原功能并增加同名入口。

**经历优化**：选择模式 → 选填岗位职责与要求 → 导入项目或科研材料 / 粘贴经历 → 查看读取清单并勾选发送片段 → 确认发送 → 逐条确认事实、补充或跳过问题 → 生成经历。名称、时间、本人角色及条目均可修改，支持按项或整体复制、再次生成和恢复以前的生成版本。证据和整理说明单独显示，不混入复制内容。

**完整简历**：按十步填写目标岗位、基本信息、教育、技能、实习工作、项目、科研、奖项、材料与事实、模板与预览。可跳过栏目或返回修改，当前步骤和已填信息保存。项目与科研沿用材料分析流程；生成后可编辑，并点击「将文稿应用到完整简历」。最后上传参考模板，确认建议或自行选择内置版式、页数、栏目顺序和显示项，生成预览并导出 Word/PDF。

姓名「张三」、电话「13333333333」、邮箱「example@example.com」为占位内容。正式导出会拦截未替换占位信息，可以明确选择「作为草稿导出」。照片可跳过，也可自行上传；不会自动生成身份照片。

## 材料与发送范围

支持文字 PDF、扫描 PDF、DOCX、TXT、Markdown、PNG/JPG，以及项目目录、ZIP 源码。单个普通文件不超过30MB；项目/ZIP最多1500条目、100MB解压或源码容量，单个源码文本512KB，最多800片段。PDF读取最多60页，其中最多6个扫描页；模型分析每次不超过9万字符、6张图片。超限、空文件、不支持的类型和失败项给出实际说明，可拆分或补选。

PDF.js 和 Mammoth 本地提取文本，分别标注页码或提取段落编号；代码标注文件及行号。扫描页和图片转换成受限尺寸图片，通过当前模型图片输入识别；不支持图片时明确失败，可切换模型或补充文本。DOCX当前读取文本，不读取嵌入图片或复刻排版，相关说明列在跳过清单，扫描内容请另外上传图片/PDF。参考模板用于栏目和风格建议，不精确复制任意图片或复杂 Word 模板。

目录和 ZIP 排除依赖、构建、版本库、凭据目录及疑似密钥文件；建立可选择的片段清单，默认仅勾选有限文本。ZIP拒绝路径逃逸、链接、加密和超限容量，不落地解压和执行代码。文件解析在独立线程中进行，可停止，超时或进程退出有提示。大项目未勾选或超出范围的内容不能视为已审阅，缺失内容应拆分或补选。

应用保存提取后的材料缓存和图片副本，原始文件不修改。材料缓存位于 `%APPDATA%/PiCareer/resume-materials/<草稿ID>`，流程与文本位于现有 SQLite 的 resume 记录中。开始分析时展示发送清单，照片不参与材料分析；模板单独分析只发送所选模板片段。分析不联网检索个人资料，不开放本机命令、文件写入工具，不执行材料内指令。数据不会自动上传，但你确认分析后，所选内容会发往当前模型供应商。

## 事实、生成与导出

文本事实的引用必须逐字存在于被读取的片段，模板中的他人事实排除。图片证据标注图片定位，识别结果仍须本人确认。个人角色、时间、指标、作者顺序、录用/发表和专利状态需要补问，允许跳过。生成仅引用确认事实、用户回答和用户输入；未知时间/角色留空，无引用及无依据的数字和部分成果状态会被拦截。人工修改会取消该条原模型证据关联，并提示用户核对；自动检查不能替代对本人贡献和事实的最终审核。

两套模板均为中文A4单栏，支持一页优先和最多两页。编辑 Word 由 docx 生成，PDF由隔离 Electron 窗口 printToPDF生成，不依赖用户安装 Python或Office。两种格式采用相同内容和栏目顺序，Word与浏览器排版细节可略有差异；PDF超出所选页数时阻止导出并提示精简或改页数。Word可编辑，后续编辑的分页以所使用的文字处理软件为准。

草稿支持自动保存、失败重试、停止、切页恢复和重启恢复。删除草稿先取消运行任务，只清理该草稿的应用缓存和记录，原项目文件及用户已经导出的文件不删除。独立版本恢复使用后台保存，不只改变界面。
