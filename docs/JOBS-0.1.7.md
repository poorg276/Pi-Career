# PiCareer 0.1.7：企业岗位检索与页面体验

日期：2026-10-10。环境：本机 Windows x64，Electron 44.7.0，现有 OpenAI Codex 授权。只调整企业岗位页字号与布局；保留 Pi 上游源码、YxAgent 和用户数据。

## 已实现

- 企业岗位页移除整条顶部栏；模型名称置于搜索卡片说明旁，可进入设置并返回。辅助文字至少 13 CSS px，摘要 14px，长模型名省略并可悬停查看；其他模块字体不变。
- 岗位检索不再把任意搜索结果直接包装成职位。六组以内的组合查询始终保留企业和城市条件，并加入招聘意图和 Agent 同义词；优先已确认的华为招聘官网入口。可选 Tavily → Bing → DuckDuckGo，没有已核实的严格结果时继续备用来源。
- 读取最多 12 篇候选正文，并发上限 3，总时限 90 秒。优先独立职位页，解析 JSON-LD JobPosting；普通正文先尝试明确标签，再由所选 Pi 模型提取，每篇模型核验最多 20 秒。
- 模型返回的字段必须逐字对应引用，引用属于同一连续职位区块。结构化多岗位分别处理；明确的多职位标签区块不能拼接，菜单城市、合作伙伴和客户不能作为对应职位的企业与城市证据。仅含 AI/大模型而没有 Agent 开发方向证据的岗位不匹配 Agent 查询。
- 严格匹配需所有填写的条件均有正文证据；相关备选需真实招聘和岗位方向相关，且至少一项条件符合。摘要不能进入严格匹配。保留引用、差异、实际来源、检索时间，不推测招聘有效性与缺失日期。重复 URL 和相同企业/职位/地点/正文的副本去重。官网入口单列，不凑岗位数量。
- 转入面试/知识点前重新读取与核验具体 JD；失败时显示原因、可编辑摘要或空输入，用户确认后再继续。目标页进入新建表单，旧计划与面试保留。返回按钮恢复原检索条件、结果、备选展开、收藏视图和滚动位置。
- 新增按 requestId 隔离的检索进度、取消和 JD 准备接口；检索状态独立于普通忙碌状态，连续检索的旧事件不能覆盖新请求。旧收藏兼容读取并标注待重新核验。

## 验证记录

类型检查与 78 项自动化测试已通过。涵盖单条件/组合条件、百科与旅游反例、合作伙伴、城市导航、多岗位串字段、相近职责、摘要不足、字段虚构、去重、6/12/3 上限、模型不可用、超时取消及既有授权/工具/学习流程。

开发版实际 Electron 在 125% 和 150% 缩放通过：页面最小字号 13px、严格/备选分组、主引擎无关结果后切换、两条 JD 返回路径与滚动恢复、收藏与模型设置返回、取消重试、旧收藏 JD 保护。连续检索和运行中切换页面额外回归通过。

真实联网开发版已使用现有模型与系统代理、无 Tavily 密钥，验证两组查询：「长沙＋华为＋Agent 开发工程师」没有已核实的严格结果，相关备选逐条标注差异；「长沙＋拓维信息＋Agent 开发工程师」取得可读取的真实招聘正例，并成功提取 JD。部分网站正文受限、部分候选达到核验时限，这些情况保留提示，不判成企业没有招聘。

## 边界与复现

公开页面可能被限流、登录限制、验证码或脚本渲染阻挡。字段核验表示页面确实提供相应证据，不代表平台或企业当前仍在招聘；未逐条联系企业确认。公开搜索及模型提取不是完整招聘数据库，可能漏掉措辞不同或无法读取的岗位。当前无需 Tavily 的真实流程已验证，真实 Tavily 付费账户本轮未验证。

本轮未重新登录 OpenAI；沿用用户已保存的订阅凭据。测试中的岗位跳转不会自动生成学习计划或面试，需用户点击下一步。检索状态仅在应用运行期间保留，不增加完整搜索历史。

```powershell
npm run check
npm test
npm run build
node scripts/jobs-check.mjs
$env:PICAREER_SCALE='1.5'
node scripts/jobs-check.mjs
node scripts/chat-check.mjs
node scripts/integration.mjs
```

设置 `PICAREER_EXE` 为发布包中的 PiCareer.exe 可检查打包版本。`node scripts/live-jobs-check.mjs --real-account` 在备份后使用本机已保存的账号完成两次公开检索及 JD 读取，断言除必要凭据刷新外全部业务记录不变。普通模拟服务验收使用独立测试目录，不写用户学习与聊天数据。
