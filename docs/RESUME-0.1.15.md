# PiCareer 0.1.15：材料导入与简历经历可靠性

## 使用变化

项目经历优化继续使用现有的岗位、经历概述、材料选择和复制流程。独立项目在概述中明确“本人独立完成”即可，不需要成员分工；团队项目说明本人负责部分。多个项目分别说明，独立贡献不自动代表论文第一作者、发表、录用或专利授权。未知时间、作者排序和未测量指标可以省略。

源码目录原来的1500个条目限制误计了无关文件。现在依赖、构建、版本控制、缓存、发布归档、链接及凭据文件先被排除，可读源码最多10000份；超出源码配额的文件在读取清单中逐项说明。目录扫描另有100000个物理条目的资源上限。ZIP保留100MB声明解压容量和100000个物理条目的防护，单个上传文件最多30MB，目录源码累计最多100MB，超过512KB的源码文件不读取。仍保留路径逃逸、加密ZIP和符号链接检查。

单次最多选择8份材料，可以继续追加；文件选择器支持解析器支持的Python、JS/TS、C/C++等源码格式。移除800个片段截断及每份材料默认只选6万字符的限制；新导入的可读文本默认勾选，发送前可按材料全选或取消。扫描PDF仍最多读取60页，其中最多6张扫描图，跳过范围明确显示。

超过单批范围的勾选内容自动分批，每批请求输入不超过9万字符、图片不超过6张。状态显示当前批次；每次模型调用最多3分钟，整次任务按批次数扩展时限。全部批次分析后合并相同事实，较大的事实集合逐层选择已有ID，不通过汇总重写事实。原始引用及位置保留，最终只采用与经历和岗位有关的部分依据，选择缩减会在材料校验说明中注明。分批会增加调用次数和耗时，不自动重试网络请求。

## 贡献与证据

分析从概述提取带连续原文引用、对应项目的个人声明，供后续写作和审核使用。已明确的独立完成或具体个人工作不因缺少外部证明再次补问。重复的贡献追问允许一次语义复核，必须引用同一项目的概述声明；已分类的成果状态、科研身份或资料冲突不能被贡献复核解除。

每条材料摘要分别核对原文位置和数字。错误摘要允许一次本批修复，仍未通过的细节排除并显示原摘要、位置和数字问题；其余依据足够时继续生成。全角数字、小数尾零及明确的“六维/6维”等维数表达可等价；不计算或推测新指标，不用未引用位置的同值数字补足依据。成稿事实ID使用简短稳定编号，引用结构错误允许一次修复，仍需重新验证并独立审核。

所有文本引用均来自本轮勾选材料。概述是用户声明，JD只是目标要求，附件中的指令不是用户指令，不执行导入代码、不联网核验个人身份。图片只能依赖模型可见内容识别，不能视作独立证明。用户仍需核对最终个人事实。暂停、取消、网络或核验失败保留旧文稿；旧草稿、材料副本、版本和后台完整简历记录保留。
